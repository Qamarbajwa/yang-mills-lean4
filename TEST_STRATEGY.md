# TEST STRATEGY

Tests are divided into four classes.

## 1. Repository governance tests
Machine-check:
- required scientific ledgers exist;
- governance YAML parses;
- canonical project ID matches;
- no theorem/proof status is pre-populated as verified without evidence.

## 2. Mathematical unit tests
When executable mathematics is introduced:
- exact symbolic identities;
- finite-dimensional analogues;
- known limiting cases;
- gauge/group invariants where computable.

## 3. Numerical regression tests
Every reproducible numerical claim must retain:
- input parameters;
- random seed;
- code/version;
- tolerance;
- expected invariant/range;
- raw output or hash.

## 4. Independent scientific verification
A mathematical result is not accepted merely because its author's tests pass.
Material lemmas require separate derivation/review according to risk.

Every test run must be recorded rather than only displayed.
